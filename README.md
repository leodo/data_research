# 投研指标工作台

基于公开数据自算的本地指标站点：恐贪指数（7 个指数）、市场情绪面板与可转债栏目。纯静态页面 + Python 数据脚本，无后端、无数据库、无第三方付费接口。

| 页面 | 地址 | 内容 |
|---|---|---|
| 首页 | `http://localhost:8040/index.html` | 导航与概览 |
| 恐贪指数 | `http://localhost:8040/indicators.html` | 7 指数恐贪值、区间切换、因子拆解 |
| 情绪面板 | `http://localhost:8040/mood.html` | 8 项综合情绪指标 + 交易拥挤度 + 9 张结构观察卡片 + 顶底共振信号板与 7 张顶底信号卡 |
| 可转债 | `http://localhost:8040/cb.html` | 2017 起长周期横截面/等权指数、近250日集思录口径、溢价率/双低/温度、双低 Top 20、全市场筛选、强赎与新债日历 |
| 暗盘行情 | `http://localhost:8040/us.html` | Hyperliquid 的美股 + 黄金/白银/布伦特油/WTI 油 + 比特币 24 小时报价、迷你走势、选中标的 K 线与盘口 |

情绪面板的 9 张结构观察卡片（均**不计入综合情绪分**）：头部 300ETF 占比、两融余额 60 日增速、全 A 站上 200 日均线占比、全 A 市净率中位数（月频）、**ERP 股债归因**、公募基金股票仓位（周频）、M1-M2 剪刀差（月频）、A 股回购规模（月频）、**重要股东增减持（月频，紧邻回购）**。其中 ERP 归因是 2026-11-20 的重点项：把 rp 变动拆成股票端(1/PE)与债券端(10 年国债)贡献，专门识别「低利率造成的便宜错觉」，并在「A股风险溢价」主卡上联动显示结论。回购与增减持同属产业资本行为、在「估值·杠杆·市场结构」栏目末尾连排：回购是**公司自己**买回股份，增减持是**大股东/董监高**买卖，主体不同、可互相印证。

**顶底信号与转折点**栏目同样不计入综合分：一个「顶底共振信号板」+ 7 张明细卡（破净率、新高新低差、上涨家数占比与动能广度、沪深300 RSI14、**阿姆氏指标 TRIN**、**市场宽广度综合指标**、**麦克莱伦摆动指标**）。信号板把 13 个维度统一成 fear 分位后输出底部/顶部共振度，用价格与宽度是否转向作独立拐点确认，并用沪深300 未来 20/60 日收益做历史胜率回测。**它回答赔率、不回答时点**，详见「口径与已知局限」。

**页面阅读顺序（2026-11-20 调整）**：总览（综合情绪分 + 历史走势）→ **顶底信号与转折点（结论前置）** → 8 张分项指标 → 交易拥挤度 → 估值·杠杆·市场结构 → 说明（含「解读有效性后视回测」全指标表）/ 注意事项。此前顶底栏目是按开发顺序追加在结构观察之后、夹在卡片中间；因顶底判断是本项目的核心诉求，现上移为「先给结论、再看支撑证据」。目录分组由 `mountToc()` 按 DOM 顺序自动扫描生成，无需手工调整分组顺序。共振板含 3 张 6–7 列的表格，必须全宽承载，因此单独用一张 `.card` 而非两列 `.panel-grid`。

**可转债栏目（2026-11-21 新增）**：独立数据链，全部使用免登录公开接口——中证指数 000832 日线、东方财富全市场转债快照与逐券纯债估值、集思录等权指数与强赎状态、同花顺新债日历。页面包含 8 个市场 KPI、中证转债/等权指数走势、**2017-11 起的长周期横截面（2017-11-17~2026-11-20，2186 个交易日，含退市券，近250日与集思录相关 0.997/0.996/0.979）**、近 250 日集思录口径、双低 Top 20 与价格-溢价率散点、309 只全市场可筛选列表、价格/溢价率分布、强赎与不强赎日历、新债申购。双低口径与集思录交叉验证：中位溢价率 67.32% 与集思录完全一致，平均双低自算 211.84 vs 集思录 212.31（样本 309 vs 311）。

## 快速开始

```bat
启动.cmd
```

两个批处理入口内容相同：`启动.cmd`（首选）与 `启动.bat`。都用 Windows CRLF 换行，双击任一个即可更新数据并打开站点。若双击 `.bat` 弹出「选择应用程序」，说明系统里 `.bat` 关联被用户级设置覆盖，双击同目录的 `修复双击关联.reg` 并确认导入即可恢复 Windows 默认关联；不导入也能用 `启动.cmd` 或下面的命令行方式启动。批处理内部统一带 `chcp 65001`，中文提示不会乱码。

或命令行：

```bash
python -m pip install -r requirements.txt
python start_site.py            # 逐步骤检查，只增量更新落后的部分，然后启动
python start_site.py --dry-run  # 只打印每个步骤的数据日期与执行计划，不动数据、不起服务
python start_site.py --force    # 忽略新鲜度，22 步全部按增量口径重跑
python start_site.py --deep     # 与 --force 同用：向子脚本透传 --force 做全历史重算（很慢，慎用）
python start_site.py --only=cb,mood  # 只允许指定分组/步骤参与更新
python start_site.py --no-browser    # 同上，但不自动打开浏览器（后台/测试）
python serve.py                 # 只起静态服务，不更新数据（调试页面时用）
```

按 `Ctrl+C` 或关闭窗口停止服务。端口固定 `8040`（`config.py` 中定义），若被占用会提示已有实例在运行。

依赖环境：Python 3.13 + akshare 1.20.65（见 `requirements.txt`）。ECharts 5.6.1 已放在 `vendor/`，页面完全离线可用。

`build_mood.py` 内部按「取数 `load_sources()` → ERP 股债归因 `build_erp_attrib(src)` → 指标注册表 `METRIC_BUILDERS` / `MACRO_BUILDERS` / `SIGNAL_BUILDERS` → 共振板 `build_turning.build()` → 组装 `build_composite()` → 输出 `write_output()`」组织，每个指标一个 `calc_*` 函数。**新增指标只需写一个 `calc_*` 并在注册表登记一行**，不用动 `main()`；卡片带 `data-toc` / `data-toc-group` 后会自动进入二级目录。ERP 归因复用 `load_sources()` 已加载的 PE / 国债序列，落盘 `mood_erp_attrib.csv` 供归因卡片与 rp 主卡警示读取，故由 `main()` 同进程调用、不单独占 DAG 节点。

`start_site.py` 的 `STEPS` 定义了显式依赖顺序与每一步的产物探针，情绪链必须按
`rebuild_turnover → build_crowding → build_etf_ratio → build_margin → build_pb → build_breadth → build_below_net → build_breadth_extra → build_arms → build_fund_position → build_money_supply → build_repurchase → build_holder_change → build_mood → build_confirm → build_factor_matrix → audit_efficacy → build_horizon_profile → build_daily_confidence → build_rsi_breadth`
执行，否则汇总脚本读到的是旧的上游数据。`build_arms.py` 必须排在宽度/成交额缓存之后（它读的是那些 CSV 与逐股缓存）；`build_confirm.py` 必须排在 `build_mood.py` **之后**（要读当天生成的 `mood_data.json` 综合分历史）；`build_factor_matrix.py → audit_efficacy.py` 顺序不可颠倒（L1 的因子值唯一来源是 L0 的 `data/factor_matrix.csv`）。这四个后置脚本都只读现有产物、只写自己的文件，不回写 `mood_data.json`。可转债链 `build_cb.py` 与前两条链无依赖，单独登记为 `group="cb"`。新增构建脚本时要同步登记到 `STEPS`，并写明 `probe`（产物日期探针）、`lag`（允许落后的交易日数）与 `depends`（读了哪些上游的产物）。

`build_turning.py` 不单独列入 DAG：它由 `build_mood.main()` 在 `load_sources()` 之后同进程调用（此时各源缓存已落盘），并生成信号卡要读的 `mood_tech.csv`。也可 `python -m workbench.pipeline.build_turning` 单独重算。

## 页面内二级目录

`mood.html`（29 个锚点，分 6 组）与 `indicators.html`（4 个锚点）在页面顶部有吸顶目录条，侧边栏同步生成二级树。一级目录是页面分组，二级是该组卡片。**默认全部展开**：目录条一次列出所有卡片（按分组标签分隔），侧栏所有分组也默认展开；点某分组 = 只看该组，点「全部展开」恢复。

- 点击卡片平滑滚动定位，卡片边框闪烁提示，地址栏 hash 同步更新，**链接可直接分享到某张卡片**（如 `mood.html#toc_pcr`）。
- 只有 1 张卡片的分组（如「交易拥挤度」）点一下直接跳转；顶底信号分组包含共振板与 7 张明细卡。
- 按 `/` 聚焦搜索框，输入名称即时过滤，`↑` `↓` 选择、`Enter` 跳转、`Esc` 关闭。
- 页面滚动时自动高亮当前卡片，但**不会**把「全部展开」视图收成单组；"收起"状态按页面记忆在 `localStorage`。

目录由 `app.js` 的 `mountToc()` 扫描 DOM 自动生成：**卡片只要加 `data-toc="名称" data-toc-group="分组"` 就会自动进目录**，新增指标不需要改目录代码。页面在 `render()` 完成后调用一次 `mountToc({app:"#app", bar:"#tocBar", side:"#tocSide"})` 即可。首页只有 4 张入口卡、一屏可见，未启用目录。

## 分项详细解读（2026-11-20 新增）

`mood.html` 每张分项卡（8 主指标 + 9 结构观察 + 7 顶底信号 + 交易拥挤度）与综合情绪分卡片下都有独立的「详细解读」区，默认全部展开、可单卡折叠或用顶部按钮一键收起。每张卡固定 8 个板块：

1. **当前读数**：区分原始值、原始值全历史分位、情绪分（反向指标已翻转）与状态，附样本量、起止日、频率；
2. **跨周期位置**：近 3/5/10 年窗口分位的含义与时代漂移判断，历史不足 10 年时明确说明「5/10 年窗口覆盖同一段样本、不构成时代对照」；
3. **近期变化**：最近 20 个观测点的原始值变化、相对幅度、方向，以及历史分位的同步变化（月/周频按观测点而非交易日计）；
4. **历史区间位置**：全历史最小值/最大值与当前值的数值距离，并说明「区间位置」与「排序分位」的区别；
5. **同类位置的历史表现**：见下方统计口径；
6. **判读逻辑**：指标衡量什么、该看趋势还是背离、关键阈值；
7. **联动观察**：应和哪些卡片交叉验证；
8. **使用边界**：常见误读与数据局限。

**第 5 项的统计口径**：`build_mood.py` 的 `hs300_close_series()` 复用 `mood_hs300.csv` 把沪深300收盘价（2002 起、当前 6034 个交易日）写入 `mood_data.json/js` 的 `hs300_close` 字段，零额外网络请求。前端取原始值历史分位落在当前 ±7.5 区间的历史观测日，按至少间隔 20 个交易日去重，要求有效样本 ≥8 且具备完整 60 个交易日前瞻数据，再算其后 20/60 交易日收益的均值、中位与上涨概率，并与「每 20 交易日取一个样本」的全历史基准对照；样本不足时直接不显示统计量。综合情绪分用自己的周频历史按同样方法分组。这是**描述性统计而非预测**，样本区间重叠、未计交易成本与分红、宏观环境不同，页面文案与注意事项⑬都写明了这一点。

**三套数字不可混用**：当前情绪分是绝对水平（0=极悲观、100=极乐观），近 3/5/10 年分位是情绪分在各自窗口内的相对排名，全历史分位是原始值的 expanding 分位（反向指标方向相反）。详细解读里逐卡提示，避免把不同量纲的数字相减。

## 动态事实、历史回放与后视验证（2026-11-20 新增）

**三者都是程序计算，不依赖 AI 运行**：`requirements.txt` 无 LLM SDK / API key，全项目无 prompt。AI 只在开发时写过「判读逻辑」「使用边界」这类代码常量，它们一次写死、不随数据变化、也不需要每次更新重新生成。

**① 动态历史结论 `D.facts`**：源码里曾写死「PCR 低 15% 分位未来 60 日 +2.6% / 高 15% −3.5%」「破净率历次大底 24.4%/14.1%/14.0%/16.6%」「TRIN>2 绝大多数是普涨日」。2026-11-20 复核发现 PCR 实际已漂移到 **+1.12% / −1.17%**，静态文案失真。现由 `build_mood.py` 的 `build_facts()` 每次构建重算并写入 `D.facts`：PCR 分档前瞻收益与全历史基准、破净率按年度最大值自动取历史前 4 大底、`mood_arms.csv` 中 TRIN>2 的普涨/普跌分布。前端用 `{@key}` 占位符在 `app.innerHTML` 出口统一替换（含 `desc` / `source` / 说明弹窗），缺失显示 `—`。**凡会随数据漂移的数字一律不得写死**。

**② 历史回放（point-in-time）**：入口在**页面最顶部的「历史回放」工具条**（橙红色，紧接目录条、在综合情绪分卡片之上；左侧目录「总览 → 历史回放」也可跳转）。原先放在「查看区间」卡片第二行，因该卡片被综合分默认展开的详细解读推到首屏外（Y≈1400px）而难以发现，故上移；区间卡片保留一行指路提示。开启后鼠标移到任意走势图（或日期框选日）即重现该日读数与全部解读。可行性来自 `core.pct_rank()` = `expanding(min_periods=20).rank(pct=True)`——`history[i].pct` 每个点只用截至当日的数据，**天然无前视偏差**。`snapshot()` 把 history 截断到 `0..i` 重算原始值分位、近 3/5/10 年窗口分位、近 20 观测点变化与历史区间；`fwdCalc()` 新增 `maxIx`，只收「样本日+60 交易日 ≤ 回放日」的已完结样本；起点晚于回放日的卡片明确标注「当日无数据」，**不会静默回退到当前值**；局部刷新不重建 26 个 ECharts，悬停 110ms 节流。**交互补强**：默认跟随鼠标容易误触，故支持**单击走势图锁定该日**（锁定后悬停不再切换、点别处可换日）、「上一天 / 下一天」与键盘 ← → 按交易日逐日切换（用注入的 `hs300_close` 作交易日历）、日期框选完自动锁定、Esc 退出；日期取自 axisPointer 的 `hoverDate` 而非 `convertFromPixel`（后者在部分图表返回 null）。顶部状态条改为**不透明实底 + 阴影 + z-index 60**（原暗色 `brand-soft` 仅 14% 不透明度，滚动时下方内容透出导致字看不清），并提供「收起」缩成右上小角标以减少遮挡。回放是「用今天的规则套当日数据」，判读逻辑仍是现行规则，**不是当天页面真实展示过的文案**——这样后视验证不会用到事后修订过的规则。

**③ 解读有效性后视回测**：说明栏目新增全指标表，按每个历史日的 PIT 情绪分（反向指标已翻转）分「悲观 <35 / 亢奋 >65」两组，20 交易日去重、需完整 60 日前瞻，统计此后 20/60 交易日沪深300收益，以**「悲观组 − 亢奋组」60 日均收益价差**判定方向（>1pp 符合预期、0.5~1pp 弱符合、±0.5pp 不显著、<−0.5pp 弱相反、<−1pp 方向相反、任一组样本 <8 记样本不足）。价差不受市场整体涨跌影响。截至 2026-11-20 的一次快照（会随数据更新变化）共 25 项：符合预期 4 / 弱符合 1 / 不显著 6 / 弱相反 2 / 方向相反 11 / 样本不足 1，已用 Python 独立复算与页面逐项一致。多数指标「方向相反」通常不是 bug，而是 A 股中短期**动量/趋势延续**：情绪亢奋常在上涨中段、悲观可延续数月，均值回归未必在 60 日内兑现——这正是后视镜要揭示的适用边界。这是方向一致性检验、**不是策略回测**：阈值为设定值、样本重叠、未做样本外检验、未计成本与分红、无因果关系。本表固定为事后全历史视角，不随回放切换；回放是当日视角，两者互补。

以上三项全部在 Python 构建期或浏览器运行期计算，`启动.bat` 更新数据后自动刷新，无需任何 AI 介入。

**图表滚动条默认窗口**：情绪面板全部 26 张走势图（含综合情绪分、顶底共振度）底部的 dataZoom 滑块，默认只框选**最近两年**（按序列末尾日期回推 24 个月换算起点；不足两年的短序列全显）。这样远古极值不会把当前曲线压平；拖动滑块或滚轮缩放仍可查看更早数据，纵轴随窗口自适应。「查看区间」的 3/5/10 年按钮仍可切换底层数据范围，与滚动条窗口相互独立。

## 数据更新策略

数据源发布时间不一致是常态（盘后当日并非所有源都出数），因此按三类区别处理，不做"一刀切"增量：

- **A 类 · 真增量**：PCR 用按日接口，读缓存末日、回溯 3 天重叠、只补后续交易日（`build_mood.py --pcr-full` 可全量重建）。
- **B 类 · 整抓即最新**：申万行业、基金指数、两融账户统计、全 A PB、基金股票仓位(`fund_stock_position_lg`)、货币供应量(`macro_china_money_supply_em`)、回购方案(`stock_repurchase_em`)等接口一次返回全历史，重抓就自动吸收新数据，无需增量。申万额外做了 31 个行业独立 CSV 缓存 + 拒绝数据倒退保护；三个 2026-11-20 新增的 B 类接口抓取失败时会沿用已有缓存，不让启动链中断。
- **C 类 · 昂贵/不稳定**：成分股强度需全量重抓（约 771 秒），按官方交易日历容忍 3 个交易日滞后，用 `*_stamp.txt` 保证同一自然日最多刷一次，失败降级沿用旧缓存。拥挤度与市场宽度按个股独立 CSV 断点续抓，已有缓存只补最近几个交易日；**且「只差最新一个交易日」时走全市场快照快路径**（`workbench/snapshot.py`，一次 `stock_zh_a_spot_sina` 请求给出 5500+ 只个股当日收盘价与成交额，逐只缓存只追加一行），把这一步从约 28 分钟降到约 1 分钟。快照仅在「今日已收盘 + 缓存末日正好是上一交易日 + 该股当日有成交」时生效，否则该股回落逐只增量（停牌股不会落行）。
- **D 类 · 纯本地派生**：宽度扩展包（NH-NL / 涨跌家数 / 动量广度）、阿姆氏指标与市场宽广度体系（`build_arms.py`，约 22 秒）、共振信号板、ERP 股债归因都复用已落盘的 CSV 与 `data/breadth_prices/` + `data/crowding_amounts/` 逐股缓存，**零个股请求**，每次运行整算一遍，不做增量以保证横截面一致性。ERP 归因直接在 `build_mood.py` 内用已加载的 PE / 国债序列计算，连文件回读都省了。

**启动器的新鲜度判定（2026-11-24 起改为逐步骤探针）**：每一步都登记了 `probe`——从自己的产物文件里读出最后数据日期，以及 `lag`——该步数据允许落后的交易日数（日频 0、T+1 发布的两融/ETF 占比与破净率 1、周频 5、月频 45）。启动时把探针日期与「应到日期」（最近已收盘交易日回退 lag 个交易日）比较，**只有落后的步骤才跑**；某步要跑时，`depends` 里登记的下游一并跑，保证汇总层不吃旧缓存。全部最新时只读探针（约 1 秒），不联网。旧实现只有「全跳过 / 全跑 22 步」两档、且用 `data/last_update.json` 按天去重——同一天里跑过一次（哪怕失败）就不再重建，真要跑时又 22 步全跑，其中拥挤度与宽度各约 28 分钟。

某步当日失败达 `MAX_ATTEMPTS`（2）次后不再自动重试（避免上游源长期故障时每次启动都白等超时），记录在 `data/step_state.json`，手动重试用 `--force`。恐贪链额外有前置守卫：先花最多 6 秒探一下隐波源 `k.csv`，不可达就直接跳过整步，源恢复后重启即自动补上，不必等它重试 3 次 × 多个 kind 的超时才降级。页面各卡片会显示真实截止日与滞后天数，请以卡片为准，不要只看全局日期。

`--force` 只表示「忽略新鲜度、全部步骤都跑」，**不再透传给子脚本**（旧版透传会让构建脚本走全历史重算，可转债一次 `--force` 曾卡死在 2017 起横截面 20 分钟以上、CPU 基本不动）；需要全历史重算时显式加 `--deep`。

`data/` 是派生产物，不纳入版本控制。克隆仓库后首次运行会重新抓取，其中全 A 个股成交额、全 A 个股收盘价各需约 20 分钟（各 5579 只）、成分股强度约 13 分钟、ETF 份额约 8 分钟，均为断点续抓，中断后重跑可继续。

## 口径与已知局限

- **全市场换手率**是分段近似：深交所数据 2021-07 后接口返回坏档，改用 2015–2021 深市×`0.72`、2022 起沪市×`1.36` 换算到全市场量级，绝对值有约 10–20% 误差，分位走势可靠。主图叠加"历史水位（分位）"线，下方另有全程同一口径的上交所官方对比图，用于跨时代比较。2024-09 后的换手率台阶是"924 行情"真实放量，非拼接错误。`rebuild_turnover.py` 一次运行同时产出主图与「上交所官方口径」对比图（后者由 2022 起沪市结果÷`1.36` 精确还原、零额外请求），两图日期严格对齐；2026-11-20 复核后主图已截断到最后一个有真实数据的交易日，避免把上一日数值插值成当天的「幽灵数据点」（官方交易日历含当天，但盘后数据可能尚未发布）。
- **PCR 方向**：A 股持仓 PCR 是顺周期指标（与沪深300 价格正相关约 +0.45），低 PCR 对应市场底部、是布局机会，与美股教科书结论相反，已用本地 1422 日样本验证。
- **A 股风险溢价 rp（2026-11-20 已修复）**：`stock_market_pe_lg(symbol=...)` 参数在 akshare 1.20.65 失效，曾误用科创板 PE(90.51) 使 ERP 为负值。现改用无参接口的全 A 平均市盈率（月频，最新 24.09），按交易日 ffill 对齐 10 年国债；历史起点由 2019 延至 2010，综合分因此由 40.2 变为 35.34（其余 7 指标零变化；2026-11-20 二次复核后为 35.32）。**注意低利率可能造成「便宜错觉」**：ERP 抬升也可能来自债券收益率下行而非股票变便宜。
- **恐贪指数隐波降级（2026-11-22）**：QVIX 唯一上游 optbbs 整站 502 时，脚本按「本地缓存 → `mood_qvix.csv`（50/300/500ETF）→ 上一版 `index_data.json` 的 volatility 序列」降级，并在 `source_note` / `qvix_fallback` 标注；没有可用序列的指数（中证1000/中证2000/创业板/科创50）会跳过并在 `indicators.html` 顶部提示，不再中止整条链或写空文件。降级期间隐波可能比最新交易日滞后 1–3 天，页面日期取实际序列末日。
- **交易拥挤度 / 市场宽度**：股票池为当前在市 A 股，存在幸存者偏差；收盘价为未复权口径，除权跳空对横截面统计影响有限；市场宽度要求个股上市满 200 个交易日才纳入。
- **全 A PB** 为月频（约 263 个月点），与日频指标不同频，区间切换按数据点计；卡片已标注"月频"。
- **破净率**：接口偶发重复日期（实测 5 条）已按日期去重；外部口径（如东财财富号）因剔除规则不同可能与本序列有 1~2 个百分点差异。
- **顶底共振信号板**：共振度 = 处于历史极值的维度占比，只度量赔率；极值可长期钝化，价格/宽度确认条件滞后，回测收益窗口重叠、未计交易成本与滑点，阈值由 `config.py` 设定且**未经样本外检验**。本地回测中「追涨确认」组并未跑赢单纯极值组，请勿据此做精确择时。顶部警戒样本仅 4 次，统计意义有限。
- **宽度扩展包**：与拥挤度共用当前在市 A 股股票池，存在轻微幸存者偏差；未复权价格的除权跳空对横截面统计影响有限；NH-NL 需个股上市满 60 个交易日。
- **ERP 股债归因（2026-11-20 新增）**：把近 250 交易日 `Δrp` 拆成 `Δ(1/PE)` 与 `−Δ(国债收益率)`，债券端占比用 `|Δbond| / (|ΔEP|+|Δbond|)` 计算（避免两端反向抵消时分母趋零产生爆炸值）。只有股票端上行才代表股票真变便宜；利率下行只是无风险利率更低。`illusion` 触发条件为 rp 抬升 + 债券端占比 ≥60% + 股票端未变便宜。当前结论：Δrp +1.174pp = 股票端 +0.952pp + 债券端 +0.222pp（占 18.9%），**股票驱动、暂未触发便宜错觉**；但 10 年国债 1.589% 处历史 0.1 分位，ERP 分位比 EP 分位高 23.2，低利率确实抬高了 ERP 的水平读数——水平分位与变动分解是两个不同视角，都已显示在卡片上。PE 为月频 ffill，股票端贡献呈阶梯状属正常。
- **阿姆氏指标 TRIN**：`TRIN = (涨家数/跌家数) ÷ (涨股总成交量/跌股总成交量)`，代数上等价于「平均每只下跌股量 ÷ 平均每只上涨股量」，衡量的是**量在涨跌两组之间的分配**，不是全市场抛压总量。经典口径用成交量，本系统用 `成交额 ÷ 未复权收盘价` 反推股数（新浪原始接口同时含 `volume` 与 `amount`，实测 sh600000 近 3 日误差 0.05%~0.4%），另保留成交额口径(Dollar TRIN)对照。逐股 5547 只 × 2885 交易日、约 1138 万条样本，TRIN 中位 0.832、1%/99% 分位 0.317/2.610，落在教科书正常区间。**A 股口径陷阱（双向）**：分子家数比在极端单边日失去上界——普跌日（上涨家数占比 <20%）趋近 0，TRIN 被机械压低（如 2026-11-19 仅 0.456），是少数上涨股吸走成交叠加全面失血，不是买盘强劲；普涨日（>80%）家数比爆炸，TRIN 被机械抬高，**不是恐慌抛售**。典型例：2026-11-05 涨 4837 / 跌 624、上涨占比 88.6%、沪深300 前一日 +2.31% 当日 +0.29%，TRIN 仍达 2.2105（成交额口径 2.6226）。全历史 TRIN>2 共 96 日，其中 67 日为普涨日、仅 1 日为恐慌日；这类日之后 20 日偏强（均值 +2.24%、胜率 63.6%）是普涨动量延续，并非超卖反弹。因此教科书「>2 = 超卖底部、<0.5 = 买盘过热」在 A 股不可机械套用，图上 0.5/2.0 只作高低参考，务必结合上涨家数占比与指数位置一起读。
- **市场宽广度体系**：宽度综合分由 6 个宽度维度的全历史 expanding 分位等权合成（至少 4 维有效才输出），McClellan 摆动值改用「净广度占比」而非经典家数差——A 股上市公司数由 2015 年约 2800 增至 2026 年约 5500，绝对家数的量纲会随时代膨胀，固定阈值无法跨时代比较。Zweig 宽度推力用 EMA10，10 日内由 ≤40% 升破 61.5% 记为触发，历史 14 次、最近 2025-04-14。
- **基金股票仓位 / M1-M2 / 回购规模 / 重要股东增减持**：仓位是第三方净值回归的**测算值**（非季报真实持仓，2017-12 起周频，机构间可差 1~3pp）；M1 统计范围在 2024 年被央行调整（纳入个人活期存款与非银支付备付金），前后绝对值不可比；回购按「方案起始月」归档、计划金额是上下限中值且未必全部实施；增减持按「公告日」归档、金额为估算值。四者金额均未经市值归一化而有长期膨胀趋势，均以历史分位与方向为主，勿跨时代比绝对值。
- **重要股东增减持（2026-11-20 新增，紧邻回购）**：数据源为东财「股东增减持」`RPT_SHARE_HOLDER_INCREASE`（`https://data.eastmoney.com/executive/gdzjc.html`），akshare 的 `stock_ggcg_em` 指向同一接口但默认要翻 4 万余页，故由 `build_holder_change.py` 直连底层 API，**按年分批 + 单页 3 次重试 + 进度文件断点续传**，首次 2015 起约 12.4 万条，日常只抓最大公告日回看 15 天的增量。实测全量 1994-08 起 14.75 万条；`CHANGE_NUM` 单位为万股（用 1994-08-05 飞乐音响 `CHANGE_NUM=146.4064` / `CHANGE_FREE_RATIO=2.8155%` 反推流通股本 5200 万股校验）。金额 = `|变动股数|(万股) × 变动时收盘价 / 10000`（亿元）：接口 `TRADE_AVERAGE_PRICE` / `REAL_PRICE` 缺失率 63%，`CLOSE_PRICE` 仅缺 2.4%，故用收盘价**估算**而非公告成交金额。归属日用 `NOTICE_DATE`（公告日）而非 `END_DATE`，否则 PIT 回放会用到当时尚未披露的信息；聚合已剔除晚于今天的盘后预挂次日公告。`MARKET` 字段区分「二级市场 / 大宗交易 / 二级市场以及大宗交易 / 其他」，最大几笔是安邦、平安的协议转让与内部划转（同一笔划转常同时记一笔增持和一笔减持，净额抵消但**虚增总额**），卡片文字给出「仅二级市场占比」界定口径，当前滚动 12 月约 62%。主口径为滚动 12 月净增持额，辅助线为增持/减持总额；当月为未完结月，滚动值会继续抬升。
- **顶底共振信号板（2026-11-20 扩展 + 复核修正）**：维度由 11 增至 13（新增 TRIN10、麦克莱伦摆动值，两者缺失时自动跳过），历史共振度与回测已同步重算，**当前数值不能与此前 11 维版本直接比较**。复核时先补「TRIN 普跌日屏蔽」，2026-11-20 二次复核又补上**镜像的普涨日屏蔽**：上涨家数占比 <20% 或 >80% 时，TRIN 因家数比失真而机械偏低/偏高，该日 TRIN 维度不计入有效维度（全历史 367 个普跌日 + 346 个普涨日 = 713 日，含当前），否则共振板会把「普涨日的高 TRIN」误读成恐慌底部极值。维度明细标注具体剔除原因（普跌日/普涨日）。修正后有效 12/13 维、底部共振 91.7、顶部 0、拐点确认 0/3，状态仍是「底部共振 · 待拐点确认」；回测中「底部极值未确认」组 60 日胜率 67.6% 仍高于「底部拐点触发」组 52.5%，结论方向未变。共振板统一对齐 2015 年起交易日历 + expanding(min_periods=250)，与单卡全历史(min_periods=20)分位略有差异属口径不同，并非计算错误。
### 2026-11-20 全量数据复核

对 8 主指标 + 8 结构观察卡 + 7 顶底信号卡 + 13 维共振板 + 7 指数恐贪逐项做独立重算（不调用原函数）与源 CSV 勾稽。结论：**所有面板的 value / 历史分位 / 情绪分计算全部正确**；破净率、两融 60 日增速、M1-M2、回购滚动、基金仓位、Wilder RSI14、BIAS20、NH-NL、TRIN 双口径、McClellan、宽度推力、换手率桥接系数 1.36、7 指数因子加权和均逐项复算一致。以下是发现并已修复的非平凡问题：

- **前端解读方向说反（唯一直接影响阅读的错误）**：`interpretation()` 原用「情绪分」判 low/high，而 `MEANING` 文案按「原始值高低」撰写，导致 3 个反向指标整体颠倒——风险溢价处 97 分位却显示「补偿被压缩、情绪偏乐观」，低估行业 76 分位却显示「低估行业偏少」，神奇指标 27 分位却显示「警惕过热」。现统一按 `pct_all` 取文案、把破净率文案的 low/high 语义一并对齐；主卡同时显示情绪分与原始值分位。
- **新基金发行有 9 年数据空白**：东财 `fund_new_found_em` 只返回 2023-01 起数据（另含 2013/2018 两个孤点），缓存却像是有 13 年历史。已剔除孤点、以 2023-01-09 为真实起点并在卡片标注「分位仅约 3.8 年样本」；当前值 13.5864 亿份不变，情绪分 0.62→0.49。同花顺 `fund_new_found_ths` 只返回在发基金、`fund_name_em` 无成立日期，均无更长历史可补。
- **综合分历史被单卡拖短**：原用 `common_start=max(各面板起点)` 裁历史，被新基金发行截到 2023-02，丢掉其余 7 指标 20 多年历史。现改为「当日至少 4 个指标有效即出分」，历史恢复到 **2003-06**（1192 周点），并在卡片标注「全 8 指标齐备自 2023-02-21 起、此前为少指标口径」。当前值始终为全部有效指标等权，仅因上一条微调 35.34→**35.32**。
- **ERP 归因卡与主卡分位不一致**：归因 CSV 落盘时 `dropna(subset=["d_erp"])` 裁掉前 250 行，同一个 rp=2.5619 在两卡显示 97.05 / 97.23。现落盘保留完整 erp/ep/bond10，取值时才筛 d_erp，两卡统一 97.23。
- **上交所官方换手率对比图从不更新**：`mood_turnover_sse.csv` 原是一次性手工文件，不在任何构建脚本或 DAG 里，已停更导致与主图日期错位。现由 `rebuild_turnover.py` 同一次运行从已抓结果 ÷1.36 精确还原，零额外请求、两图日期严格对齐；并修掉主图把上一日数值插值成当日「幽灵数据点」的问题。
- **文案与代码不符 / 死代码**：股基 3 年年化代码 `shift(732)`、文案写 756；新基金发行「近 90 日日均」实为「窗口内各发行日平均单日份额」；文件头把正向指标误标「反向指标」。均已改正，并删除 `fetch_total_mv()` 死代码；`mood_all_pe.csv`(PE 90.51) / `mood_total_mv.csv` 标注为历史遗留坏缓存、无消费者。

- **分项详细解读的前瞻收益统计**：分组依据是原始值历史分位（不区分指标方向），样本按 20 交易日去重但仍可能区间重叠，基准为全历史每 20 交易日取样，两者时段分布不同；均值高于基准只是历史描述，不构成看涨依据。历史不足 10 年、当前读数贴近历史极值或月/周频数据源，都可能导致有效样本 <8，此时页面明确显示「样本不足」而不给统计量（当前仅「新基金发行」一卡如此）。
- **申万行业**、**50ETF QVIX**、**两融账户统计**等源可能滞后数日；`allmarket` 恐贪常因此停在前一交易日。这属于数据源节奏差异，不是脚本故障。
- 口径系数（换手率桥接、市值锚、均线窗口、抓取参数等）集中在 `config.py`，注释里写明了实测依据。中证1000 QVIX 回归系数是运行时拟合的，不是固定常量。

## 因子研究层：L0 变换 / L1 常驻审计（2026-11-21 新增）

解决的问题：24 张卡片 + 确认层的 `history.pct` 都是「全历史 expanding 分位」，但跨年分布并不平稳（跨年 KS 均值 0.435，ERP 与时间秩相关 +0.793、头部300ETF占比 +0.838）。直接把不同量纲、不同漂移类型的原始值或单一分位丢进相关/回归，会同时踩同源共线、混频错配、多重检验三个坑。本层把「因子预处理」和「效力判定」拆成两级常驻模块，**只读、零网络、不进综合分、不改共振板**。

| 层 | 脚本 | 输入 | 输出 |
|---|---|---|---|
| L0 变换 | `build_factor_matrix.py` | `mood_data.json`（卡片 `history.value` + `history.pct`、`composite`、`hs300_close`） | `data/factor_matrix.csv`（2638 交易日 × 205 列）、`factor_matrix.json/.js` |
| L1 审计 | `audit_efficacy.py` | **L0 的 CSV（因子值唯一来源）** + L0 元数据 + `mood_data.json` 的市场状态 | `data/efficacy_audit.json/.js`（`window.EFFICACY_AUDIT`） |
| 公共层 | `factor_utils.py` | — | PIT 变换、KS / Spearman / BH-FDR / 块 bootstrap、json/js 精确双写 |

**L0 双轨原则**：`pct_exp` 就是卡片现用分位，原样保留以保证综合分 34.65(8/8) 与已交付报告的历史可比性；并列生成 `raw / pct_r126 / pct_r250 / pct_r500 / z_r250 / robust_r250 / detrend_r500 / chg60 / logmod / logit_pct / dual_gap` 共 12 种变换，全部 trailing/expanding、只用 t 及之前信息。启动时做 64 次「截至 t 的子样本重算末值 vs 全量序列」PIT 回放（本次最大差 0），并校验生产轨道与卡片 `pct` 的 ffill 完全一致。25 个因子全部补齐 `unit / kind / transform / window / freq / history_start / as_of / publish_date / stale_days / coverage_pct` 元数据；**源端确实没有 `publish_date`，如实写 `null`**，用 `as_of` + `stale_trade_days` 近似。月/周频 8 个因子只登记元数据、不进日频矩阵，避免 ffill 造伪独立观测。

> `factor_matrix.json` 的 `factors` 数组必须保持生产卡片顺序（`panels → macro → signal → composite`）。L1 的块 bootstrap 按此顺序消耗随机数，重排会使首版 51 次主检验的 p 值不可复现；需要排序请在展示层做。

**L1 相对首版的升级**：① 因子值统一从 L0 CSV 取，输入口径唯一；② 条件 IC（8 状态 × 17 因子 = 136 次）也纳入 BH-FDR，给出族内校正 + 与主检验合并的联合校正（187 次）；③ 新增多轨道稳健性（换变换后 IC 秩相关与符号翻转率）；④ 写试验日志登记每轮检验族系，应对「跑一批 → 看结果 → 加指标 → 再跑」的序贯检验；⑤ 保留首版全部字段与贝叶斯示范，51 次主检验可逐条复现。

**运行方式**

```bash
python -m workbench.pipeline.build_factor_matrix    # L0，约 2 秒，零网络
python -m workbench.pipeline.audit_efficacy         # L1，约 35 秒（块 bootstrap 1200 + 条件 300）
python start_site.py             # 正常启动会自动带上这两步（DAG 末尾）
```

**当前结果（基准 2026-11-20）**：主检验 51 次 raw `p<0.05` 仅 2 个、BH-FDR 后 **0 个**；条件 IC 136 次 raw 17 个、族内 FDR 后 **2 个**、联合 187 次校正后仍是这 2 个（均在「高波动 × 宽度类」，IC 为负）。条件 IC 的 p 用 300 次块 bootstrap，分辨率下限 1/300，`q=0` 应读作「低于分辨率下限」而非精确 0。多轨道显示换变换会显著改变结论（`dual_gap` 与主轨道 IC 秩相关 −0.583、符号翻转 58.8%），印证变换必须按经济含义先验指定。**在 walk-forward 样本外证明有稳定增量之前，绝不改 8 指标等权。**

`mood.html` 底部新增独立栏目「因子研究层」，由 `factor_audit_cards.js` 渲染（4 张卡片 + 3 图：变换 KS、代表因子逐年路径、条件 IC 热力），浅/暗主题跟随、自带 `data-toc` 并在填充后重扫目录；缺失数据只提示本层，不影响原有面板。

**边界**：本层不证明任何变换更有效；KS 降低是分位压平分布的设计使然；条件 IC 状态含阈值、样本重叠、未经样本外检验，显著格子只作假设生成。详见 `reports/指标效力审计与回测方案-20261121.html` 与 `reports/因子预处理与量纲漂移诊断-20261121.html`。

- **双低 = 价格 + 转股溢价率（百分点）**；溢价率取东财 `TRANSFER_PREMIUM_RATIO`，纯债溢价 = 现价 / 纯债价值 − 1。
- 自算横截面与集思录交叉验证：309 只（集思录 311 只，差异为报价/停牌口径），中位溢价率 67.32% 完全一致，平均双低 212.31（集思录）vs 211.84（自算），差异来自样本差。
- **长周期（2017-11-17 起，2186 个交易日）**：用东财逐券历史（含退市券）按日复算，当前样本 313 只；近 250 日与集思录相关性：中位溢价率 0.997、平均双低 0.996、温度代理 0.979。2017-11 起步样本 30 只，2018 年后逐步增至 300+。
- 长周期等权指数为**价格等权**（不含强赎转股收益与交易成本），2017-11-17 基准 1000；页面同时给出中证 000832 同起点归一曲线。
- 长周期温度代理 = 中位价格近 500 日 z-score 的 logistic 映射（0–100），**不是集思录官方温度**；集思录温度仅近 250 日，两者在重叠期相关 0.979。
- 集思录匿名接口只返回近 250 日指数历史、列表只给前 30 条，因此全市场快照改走东财；长周期由东财逐券历史自算，不依赖会员接口。
- 逐券纯债估值按 `data/cb_cache/valuation.json` 缓存，**每个交易日刷新**一次，合并时允许滞后 5 个交易日；长历史缓存在 `data/cb_cache/history.csv`（约 50MB），首次全量约 5–10 分钟，之后只增量抓活跃券自上次缓存日以来的新增行（通常 1–5 个交易日，数秒到几十秒）。`--force` 全量刷新。强赎日期以公司公告为准。
- **增量分层**：快照类（东财列表、集思录指数/强赎、中证指数、新债）每次全量但都只有几 MB、几秒；纯债估值逐券缓存、只抓缺失/过期券；长历史只抓活跃券新增行，退市券走缓存。可转债链已登记为 `start_site.py` 的 `PIPELINES["cb"]`，并由 `check_freshness()` 作为第三份数据检查；同一天重复启动按 `last_update.json` 跳过，需重跑用 `--force`。与现有系统一致，采集发生在 `start_site.py` 启动时，不是常驻定时任务；跨日需重启 `启动.cmd`（或由计划任务触发）。

## 暗盘行情栏目（2026-11-22 新增）

`us.html` + `us.js` + `us_dark.py`：把 Hyperliquid HIP-3 上的美股永续、黄金 / 白银 / 布伦特油 / WTI 油，以及主交易所的比特币做成 24 小时行情页。全部使用公开接口，无需 API Key、无需连接钱包，也**不新增 Python 依赖**（WebSocket 客户端用标准库 socket/ssl 实现 RFC6455，含分片、ping/pong、close 与重连退避）。

| 快照 | `data/us_dark/latest.json`（最新全量）+ `data/us_dark/snapshots/YYYYMMDD.jsonl`（每行一次 5 秒快照，保留 7 天） |
| 按需采集 | 20 秒无心跳断开 WS；切栏目 / 标签页隐藏 / 栏目滚出视口立即停止请求 |

**为什么要有后端**：浏览器直连 wss 会碰到跨域、证书与页面关闭后的连接残留；由站点进程维持一条 WS，页面只读同源快照。`serve.py` 与 `start_site.py` 都已挂载 `/api/usdark/*`，因此更新后**必须重启站点进程**（`启动.cmd`）——旧进程没有这个路由，页面会明确提示"行情接口未就绪"。

**诚实展示的三条规则**：

1. 最新成交价只由 `trades` 推送更新，并保留交易所成交时间；没有新成交时价格一动不动，只更新「最后成交 x 秒前」。
2. 报价更新时间来自 `bbo.time`，深度面板另有自己的更新时间；超过 60 秒无成交标「报价中」，连盘口也超 60 秒标「报价停滞」，**不拿 markPx 冒充成交价**。表格把这层信息合并为「更新状态」一列（徽标 + 报价时间）。
3. 价格单元格只在 `last_trade_ms` 变化时闪动；轮询到相同价格不产生任何动画。

**目录刷新保护（2026-11-22 修复）**：目录刷新必须全部分组成功才替换；任一分组临时失败时**保留旧目录**、30 秒后重试，绝不缩容退订。此前 `xyz` 的 `metaAndAssetCtxs` 偶发失败、只拿到主市场 BTC 时，旧逻辑会把 61 个股票从目录中删掉并退订，页面于是全表永久「报价停滞」且不会自行恢复。

**走势列可靠性（2026-11-22 修复）**：`/sparklines` 批量抓 66 个标的时偶发只成功 22/56/61 个；旧逻辑把部分结果缓存 5 分钟、前端整体替换，缺失标的就显示空白。现在后端对缺失标的补抓一轮、部分成功与旧缓存合并，前端也合并而非覆盖，并用 localStorage 保留最近一次走势/前一日；覆盖不足 95% 时 30 秒重试。

**恢复机制（2026-11-22 修复）**：页面切后台 20 秒无心跳会主动断开 WS；切回时先连 WS 并订阅（约 1 秒），目录刷新改为后台线程，不再阻塞 pong；目录失败保留旧目录并 30 秒重试；空 sparklines 响应不再缓存 5 分钟，改为 30 秒重试。这样切回后不会长时间全表「报价停滞」，迷你走势/前一日也会自动补上。

**「收盘以来」与「前一日」口径（2026-11-23 调整）**：

- **收盘以来**：最新成交 ÷ 上一美股交易日 16:00 ET 收盘 − 1，随最新成交实时变化；周末看到的就是周五收盘后的累计涨跌。
- **前一日**：上一美股交易日 16:00 ET 收盘 ÷ 再前一交易日 16:00 ET 收盘 − 1，周末保持不变。

周末该值保持不变，所以周六/周日看到的就是周五收盘的涨跌；周中看到的是上一个完整交易日。计算复用 mini 走势的 7 天 1h K 线（同一批请求），缓存 5 分钟；商品/加密也按同一 16:00 ET 切点，便于横向比较。节假日没有单独剔除，长假期间若该时刻无 K 线则显示 `—`。拆股/并股会在某一根 1h K 线上留下「open / 上一根 close ≈ 1/N」的跳变（如 SNDK 8:1），对 >65% 的向下跳变会尝试按最接近的整数比例还原，并用「拆N」标注（如 `拆8`）；无法识别时原样显示。

**表格与布局**：第一列以**中文名为主**（13.5px 加粗）、代码为辅（10px 灰色），详情标题和顶部摘要同样是「英伟达（NVDA）」的顺序。买一 / 卖一 / 中间价 / 价差不再占表格列，统一放到右侧「选中标的」卡片；「报价更新」与「状态」合并为「更新状态」。表格右侧是选中标的的 24h K 线（5 分钟）与买卖盘摘要，点击任意行即切换；窄屏（≤1480px）自动改为上下排列，桌面 1500+ 时左侧表格约 750px、右侧卡片约 460px。

**标的口径**：HIP-3 的 meta 只给代码、不标"是否美股"，因此用 `config.py` 的 `US_DARK_MARKETS` 白名单（当前 66 个：61 个美股正股/ADR + 5 个商品；商品为 `xyz:GOLD` / `SILVER` / `BRENTOIL` / `CL`，数量单位随品种为盎司 / 桶，外加主交易所的 `BTC`——它没有 DEX 前缀，单独放在 `US_DARK_MAIN`），并自动剔除交易所标记 `isDelisted` 的市场（实测 ACN / SNAP / SNOW / SMCI 等已下架）。想加标的加一行 `("xyz:XXX", "中文名", "美股" 或 "商品")` 即可；`vntl` 的 Pre-IPO 市场 2026-11-22 实测全部下架、成交额为 0，故 `US_DARK_PREIPO` 默认留空。新增标的需重启站点进程才会进入后端目录（前端表格按 24h 成交额排序，中文名为主、代码为辅；首屏默认选中成交额最大的美股，避免 BTC 的主市场成交量把首屏带到加密品种）。

**接口**：

```bash

curl "http://127.0.0.1:8040/api/usdark/candles?coin=xyz:NVDA&interval=5m&hours=24"
```

`/state` 同时是心跳：`focus` 决定详情卡订阅哪个市场的 `l2Book`。`/health` 不续约心跳，可用于观察「无人观看时是否已断开」。`serve.py 8041` 可另起一个端口做本地验证。

## 常见问题

- **启动时大量 `AttributeError: module 'akshare' has no attribute ...`**：环境里的 akshare 与 `requirements.txt` 锁定的 1.20.65 不一致（如 1.17.8 没有 `calendar_trade_date_hist_sina` / `index_zh_daily_sina` / `stock_zh_a_spot_sina`）。运行 `python -m pip install -r requirements.txt` 即可；`start_site.py` 现在会在更新前检查这三个接口，缺失时直接跳过数据更新并用现有数据启动，不再刷 20 多段 traceback。
- **恐贪指数提示「隐波源不可用」**：QVIX 的唯一上游 `optbbs.com` 会整站 502。`build_fear_greed.py` 会依次降级到本地缓存、`data/mood_qvix.csv`、上一版 `index_data.json` 的隐波序列，并在卡片与 `qvix_fallback` 字段标注来源；确实没有缓存时只跳过受影响的指数并在页面顶部提示，不再写空文件。源恢复后重跑 `python -m workbench.pipeline.build_fear_greed` 即补齐。
- **双击 `启动.bat` 弹出「选择应用程序」**：改用 `启动.cmd`（关联与 `.bat` 独立），或双击 `修复双击关联.reg` 导入后重启资源管理器；也可右键 → 打开方式 → 选择「Windows 命令处理器 / 命令提示符」并勾选「始终使用此应用」。
- **一直显示"数据加载中"**：确认是通过 `http://localhost:8040/...` 访问而非直接双击 HTML（`file://` 下 fetch 会被拦截）。
- **数据日期不齐**：正常现象，卡片上的"数据至 YYYY-MM-DD"才是真实截止日。
- **想强制刷新**：`python start_site.py --force`（全部步骤按增量口径重跑，不向子脚本透传 `--force`）；确实要全历史重算再加 `--deep`。只想看哪些步骤落后而不跑数据，用 `--dry-run`。
- **改错了想回滚**：`git log` / `git diff` 可用；`archive/` 保存了治理前的旧版脚本快照。
- **改配色**：只改 `app.css` 的 `:root` / `[data-theme="dark"]` 即可，四页共用。
- **新增卡片没进目录**：确认元素上有 `data-toc` / `data-toc-group`，且 `mountToc()` 在 `innerHTML` 赋值之后调用。
- **目录挡住卡片标题**：目录条吸顶偏移是动态计算的；若调整了 `.topbar` 高度，检查 `app.js` 的 `offset()`。
