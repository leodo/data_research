# 投研指标工作台

基于公开数据自算的本地指标站点：恐贪指数（7 个指数）与市场情绪面板。纯静态页面 + Python 数据脚本，无后端、无数据库、无第三方付费接口。

| 页面 | 地址 | 内容 |
|---|---|---|
| 首页 | `http://localhost:8040/index.html` | 导航与概览 |
| 恐贪指数 | `http://localhost:8040/indicators.html` | 7 指数恐贪值、区间切换、因子拆解 |
| 情绪面板 | `http://localhost:8040/mood.html` | 8 项情绪指标、拥挤度、估值与宏观比较 |

## 快速开始

```bat
启动.bat
```

或命令行：

```bash
python -m pip install -r requirements.txt
python start_site.py            # 按需更新数据并启动，自动打开浏览器
python start_site.py --force    # 强制重建全部数据后再启动
python serve.py                 # 只起静态服务，不更新数据（调试页面时用）
```

按 `Ctrl+C` 或关闭窗口停止服务。端口固定 `8040`，若被占用会提示已有实例在运行。

依赖环境：Python 3.13 + akshare 1.20.65（见 `requirements.txt`）。ECharts 5.6.1 已放在 `vendor/`，页面完全离线可用。

## 代码结构

```
编排层   启动.bat → start_site.py          新鲜度判定 + 显式 DAG 编排 + 静态服务
计算层   build_fear_greed.py              7 指数恐贪（独立链）
         rebuild_turnover.py             全市场换手率（交易所口径）      ┐
         build_crowding.py               交易拥挤度                      ├ 情绪链上游
         build_etf_ratio.py              头部 300ETF 占比                ┘
         build_mood.py                   情绪面板汇总 + 输出
公共层   core.py                          路径/日期/日志/缓存/分位/交易日历
         app.js                           前端主题变量与十字准星 helper
数据层   data/                            CSV 缓存 + JSON/JS 输出（派生产物，不入库）
展示层   index.html / indicators.html / mood.html / vendor/
```

`start_site.py` 的 `PIPELINES` 定义了显式依赖顺序：情绪链必须按 `rebuild_turnover → build_crowding → build_etf_ratio → build_mood` 执行，否则汇总脚本读到的是旧的上游数据。新增构建脚本时要同步登记到这里。

## 数据更新策略

数据源发布时间不一致是常态（盘后当日并非所有源都出数），因此按三类区别处理，不做"一刀切"增量：

- **A 类 · 真增量**：PCR 用按日接口，读缓存末日、回溯 3 天重叠、只补后续交易日（`build_mood.py --pcr-full` 可全量重建）。
- **B 类 · 整抓即最新**：申万行业、基金指数等接口一次返回全历史，重抓就自动吸收新数据，无需增量。申万额外做了 31 个行业独立 CSV 缓存 + 拒绝数据倒退保护。
- **C 类 · 昂贵/不稳定**：成分股强度需全量重抓（约 771 秒），按官方交易日历容忍 3 个交易日滞后，用 `*_stamp.txt` 保证同一自然日最多刷一次，失败降级沿用旧缓存。

启动器的新鲜度判定不看"数据日期是否等于今天"（那样会因个别源永远滞后而每次启动都重建），而是用 `data/last_update.json` 记录**今日是否已尝试更新**；同一天重复启动直接跳过，需要重跑用 `--force`。页面各卡片会显示真实截止日与滞后天数，请以卡片为准，不要只看全局日期。

`data/` 是派生产物，不纳入版本控制。克隆仓库后首次运行会重新抓取，其中全 A 个股成交额（5579 只）约 20 分钟、成分股强度约 13 分钟、ETF 份额约 8 分钟，均为断点续抓，中断后重跑可继续。

## 口径与已知局限

- **全市场换手率**是分段近似：深交所数据 2021-07 后接口返回坏档，改用 2015–2021 深市×`0.72`、2022 起沪市×`1.36` 换算到全市场量级，绝对值有约 10–20% 误差，分位走势可靠。图中同时叠加了上交所官方口径与"历史水位（分位）"线，用于跨时代比较。2024-09 后的换手率台阶是"924 行情"真实放量，非拼接错误。
- **PCR 方向**：A 股持仓 PCR 是顺周期指标（与沪深300 价格正相关约 +0.45），低 PCR 对应市场底部、是布局机会，与美股教科书结论相反，已用本地 1422 日样本验证。
- **A 股风险溢价 rp**：`stock_market_pe_lg` 的 `symbol` 参数已失效，当前实际用的是科创板 PE，该值失真，暂未替换数据源。
- **交易拥挤度**股票池为当前在市 A 股，存在幸存者偏差，早期年份拥挤度略偏高。
- **申万行业**、**50ETF QVIX** 等源可能滞后数日；`allmarket` 恐贪常因此停在前一交易日。这属于数据源节奏差异，不是脚本故障。

## 常见问题

- **一直显示"数据加载中"**：确认是通过 `http://localhost:8040/...` 访问而非直接双击 HTML（`file://` 下 fetch 会被拦截）。
- **数据日期不齐**：正常现象，卡片上的"数据至 YYYY-MM-DD"才是真实截止日。
- **想强制刷新**：`python start_site.py --force`，会透传给所有构建脚本。
- **改错了想回滚**：`git log` / `git diff` 可用；`archive/` 保存了治理前的旧版脚本快照。
